Level 0 DFD — Context Diagram

High-level view: the system as a single process interacting with its three external entities

Context Diagram notes: The system is treated as a single black-box process. All three external entities—Barangay Official (admin), Barangay Staff (operator), and Resident (client)—exchange data with the system boundary. Solid arrows represent incoming data flows (inputs); dashed arrows represent outgoing data flows (outputs).
L1

Level 1 DFD — Module Decomposition

Data flows between the 5 functional modules and the centralized database

Level 1 notes: Each numbered process (P1–P5) is a module in the system. D1 represents the centralized database. Solid arrows indicate write/store operations; dashed arrows indicate read/retrieve operations. Grey dashed lines show inter-module data dependencies (e.g., the Document module queries Profiling data for resident verification).

Architecture notes: All three user types communicate with the application server over HTTPS. Laravel's middleware layer handles authentication and role-based access control before routing requests to the appropriate module. All modules share a single centralized database via an ORM (Eloquent). The Analytics Dashboard is read-only and queries data across all modules.
